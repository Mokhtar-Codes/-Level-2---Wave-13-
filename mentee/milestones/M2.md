## What you're building

Your Expense Tracker gets a **screen** and becomes **usable**. By the end, someone who's never seen your code can open the page, add an expense, mark it paid, and delete it — without touching the console.

M1 was the data and the logic. M2 is everything the user sees and does.

---

## What you get this time

**No worked example.** In M1 you had the whole Task Tracker to build a parallel from. This time you get `M2-skeleton.js` and `M2-skeleton.html`: the **shape** of the app with every part marked `TODO`.

There's also `M2-starter.css` — rename it to `style.css` and your page will look like something from the first render. It covers the page, the form and the buttons, so your time goes on JavaScript. **One rule is left empty for you**: what a paid expense looks like. That one's a decision, not a chore.

That's deliberate. The structure is the thing worth keeping — you'll use it for every app you build from here, including in React. The code inside it is yours to write.

The Session 7 and 8 READMEs have working Task Tracker code in their "Where this lands in the project" sections. Read them, understand them, then write yours without them open.

## Stage 1 — after Session 7, due Session 8

**Getting it on screen.**

- [ ] Three files: `index.html`, `style.css`, `app.js`, with `<script src="app.js" defer></script>`
- [ ] Your M1 expenses array, with **an `id` added to every expense** (just number them 1, 2, 3 for now)
- [ ] `createExpenseElement(expense)` — **destructure in the parameters**, return **one** `<li>`. It does not touch the page
- [ ] `render()` — clears the list, loops the data, appends one element per expense
- [ ] **One CSS class** that changes how paid expenses look — faded, a different edge, whatever you like. JavaScript adds the class; CSS decides the look (the empty `.paid` rule in the starter file is where it goes)
- [ ] A **summary line** on the page: how much is still unpaid, and how many expenses there are. Reuse your M1 functions
- [ ] An **empty state**: with no expenses, the list is empty and the summary says something sensible
- [ ] `render()` called once at the bottom

**Test the empty state before you move on.** Comment out your expenses and reload.

## Stage 2 — after Session 8, due Session 9

**Making it work.**

- [ ] A **form** on the page: what the expense was, how much, and a category
- [ ] Adding an expense:
  - [ ] Listen for the form's **`submit`**, not the button's click
  - [ ] `event.preventDefault()`
  - [ ] The amount must end up as a **number**, not a string
  - [ ] **Ignore empty input** — no blank expenses
  - [ ] New expenses get a **unique id**
  - [ ] Clear the inputs afterwards
- [ ] **Mark paid / unpaid** — a button on each expense that flips it
- [ ] **Delete** — a button on each expense that removes just that one
- [ ] Every one of those changes the data, then calls `render()`. **Nothing pokes at the page directly**
- [ ] Your file keeps the four sections: **data**, **data changes**, **drawing**, **listening**

---

## Rules

1. **Change the data, then render.** Never reach into the page to patch one item. If you find yourself doing that, the data is the thing to change.
2. **Drawing functions never change data. Data functions never touch the page.**
3. **Only what we've covered — Sessions 1 to 8.** `REFERENCE.md` covers the whole course; being in there doesn't mean it's ready to use.
4. **Use `createElement` and `textContent`, not `innerHTML`**, for anything a user typed.
5. **Keep the console open** while you work. Every bug you hit today has an error message waiting there.

---

## When you're stuck

Check these in order — they're the four bugs everyone hits:

1. **Nothing on the page, `Cannot read properties of null`** → your selector doesn't match your HTML id. Check both files.
2. **The page shows `undefined`** → your `createExpenseElement` doesn't `return` the element.
3. **Everything appears twice** → `render()` isn't clearing the list first.
4. **You click and nothing happens, no error** → your handler changed the data but never called `render()`. Check by logging the data.
