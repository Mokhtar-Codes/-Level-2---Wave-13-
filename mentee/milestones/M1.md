## What you're building

An app that keeps track of your expenses — rent, coffee, subscriptions — and tells you useful things about them: what's still unpaid, what you've spent, what to pay first.

It's **your** app. It runs alongside the Task Tracker we build in class, all course. Same structure, different data. By M3 it will have a screen, remember everything after a refresh, and pull live exchange rates from the internet.

M1 is the foundation: **the data, and functions that understand it.**

---

## Where to build it

`milestones/expense-tracker-starter/` has an empty folder set up for you — copy it into **your own repo** as `expense-tracker/` and start there. `app.js` opens with the two questions to answer first.

## The example

`M1-example.js` is the Task Tracker, console version. **Read it and run it before you start.**

It's the parallel to your app. Notice:

- A **design check** comment at the top — shape in English, then one example item
- Three sections: **data**, **functions**, **output**
- Every function takes **one task** and **returns** something
- The only `console.log`s are in the output section

Build yours with the same structure. **Don't copy it line by line** — every name, property and message in yours should be about expenses. If your code still says `task` anywhere, you've copied instead of built.

## It grows in three stages

You don't have loops or array methods yet. That's fine — M1 grows as you learn them.

### Stage 1 — start now, after Session 4

- [ ] **Design check** at the top of your file, as a comment: what shape is an expense, in plain English — and one example expense
- [ ] An array of **at least 5 expenses**. Each needs at least:
  - a label (text)
  - an amount (a **number** — not `"45"`)
  - a category (text)
  - whether it's paid (a boolean)
- [ ] Mix it up: some paid, some unpaid, at least 2 categories, at least one over $100
- [ ] `describeExpense(expense)` — **returns** a sentence about one expense, like `Internet — $45 (home, unpaid)`
- [ ] `getPriority(expense)` — **returns** a label using `if` / `else if`: `"Paid"` for paid expenses, `"Pay first"` for unpaid ones over $100, `"Unpaid"` for the rest. **Add a comment explaining why your checks are in that order**
- [ ] Output: log `describeExpense` and `getPriority` for a few expenses, by index — `expenses[0]`, `expenses[1]`…

### Stage 2 — after Session 5 (loops)

- [ ] Replace the by-index lines with a **loop** that describes every expense
- [ ] `getTotal(expenses)` — **returns** the total of all amounts
- [ ] `getUnpaidTotal(expenses)` — **returns** the total still to pay
- [ ] Use **destructuring** at least once

### Stage 3 — after Session 6 (array methods), due before Session 7

- [ ] `getUnpaid(expenses)` — **returns** a new array of only the unpaid expenses, using `filter`
- [ ] `getLabels(expenses)` — **returns** an array of just the labels, using `map`
- [ ] `findExpense(expenses, label)` — **returns** the expense with that label, using `find`
- [ ] Your output handles `findExpense` finding **nothing** — search for something that isn't there, and show a sensible message instead of crashing
- [ ] Rewrite at least one of your Stage 2 loops with an array method, if one fits. Keep a `for...of` for any sum — that's fine

## Rules

1. **Functions return. Only the output section logs.** No `console.log` inside any function.
2. **Only use what we've covered so far — Sessions 1 to 6.** `REFERENCE.md` covers the whole course, so something being in there doesn't mean it's ready to use. If it isn't in a README you've already read, don't use it yet.
3. **Every function answers the two questions.** You should be able to say what it needs and what it gives back.
4. **Amounts are numbers.** Check with `typeof` if you're not sure.

## What "done" looks like

When Stage 3 is finished, running your file should print something like this. Yours will have different data and wording — that's the point.

```

Still to pay: $195
Unpaid: [ 'Internet', 'Gym' ]
No expense called "Holiday"
```
